# SITE-TOPOLOGY-SELECTION-AUTHORITY-01

Status: queued after exact-URL/final-custody convergence
Mode: BUILD
Proof class: offline_product_path_proof
Depends-on: EXACT-URL-ACQUISITION-AND-FINAL-CUSTODY-CONVERGENCE-01
Does-not-authorize: live calls, provider-order-as-relevance, automatic Map-to-Crawl, Crawl page custody, general Deep, candidate manufacture, or downstream authority by assertion

## Outcome

Activate bounded `MAP_SITE` beneath the installed RunKernel acquisition chain,
admit its site-topology artifact as canonical acquisition material, and install
one explicit topology-selection proposal/decision owner that can admit an
exact URL for a subsequent READ or FOCUSED_EXTRACT operation.

Map returns topology only. It does not return evidence, search relevance,
source authority, or a ranked candidate list.

## Installed Starting Point

- The acquisition controller already recognizes an exact HTTP(S) site root with
  `site_topology` material shape and returns
  `map_candidate_reentry_not_installed` before routing.
- `core.routing` already catalogs Tavily Map, and the low-level adapter
  normalizes at most 100 same-site URLs into
  `AcquisitionArtifactKind.SITE_URL_TOPOLOGY` with root, URL list, digest, and
  truncation posture.
- RunKernel already owns one-active-operation, route, execution, terminal, and
  exhaustion semantics. No Map PRODUCT transport or topology-selection owner is
  installed.

## Required Build

1. Replace the current Map blocker only after identifying one real ordinary
   producer of exact root, active source obligation, current component lineage,
   and `site_topology` need.
2. Execute Map through the existing proposal-to-terminal RunKernel chain and
   retain one canonical topology observation bound to the exact Map work order,
   route, terminal receipt, root, URL-list digest, and current lineage.
3. Add an advisory topology-selection proposal contract that can reference only
   URLs present in that canonical topology. The proposal must bind its producer,
   selection reason, target material shape, current contract/component/
   obligation, topology receipt, and exact URL(s). It must contain no provider
   identity, relevance score supplied by provider order, evidence claim, or
   executable free-form instruction.
4. Add a deterministic RunKernel URL-selection authorization and reducer. The
   accepted selection must reprove topology membership, lineage, scope, stale
   and duplicate state, and the next exact material need. RunKernel, not the
   orchestrator or provider response order, admits the selected URL.
5. Re-enter the installed acquisition controller with a fresh READ or
   FOCUSED_EXTRACT proposal. Extend the proposal with a distinct canonical
   topology-selection/known-URL ref when needed; never impersonate a
   `SearchResultCandidatePacket` candidate. Preserve the full second-operation
   identity and parent Map receipt lineage; do not silently chain inside an
   adapter.
6. Keep the orchestrator to sequencing and observation submission. Do not place
   URL-selection heuristics or Map-to-operation policy in
   `core.pipeline_orchestrator.py`.

## Selection Boundary

Provider-returned order is descriptive only and cannot become relevance.
Deterministic selection must consume repository-owned admitted facts. If no
current fact can distinguish a relevant URL, stop for a product/semantic
selection decision; do not select the first URL, invent a score, treat all URLs
as candidates, or crawl them.

A selected topology URL is an exact known URL for the next acquisition. It is
not a manufactured `SearchResultCandidatePacket` record. Any future decision to
create a broader candidate class requires a separate contract and authority
phase.

## Verification

- Exact root need derives Map and no longer hits the old blocker only in the
  licensed ordinary composition.
- Exactly one Map route, transport, execution, terminal receipt, and topology
  observation occur; stale/root-mismatched/out-of-scope URLs fail closed.
- Selection proposals are advisory and provider-neutral; RunKernel admits only
  topology-member URLs under current lineage.
- Provider order, mode, complexity, and availability do not select a URL.
- The selected URL re-enters the existing READ/FOCUSED_EXTRACT chain with a new
  exact authorization; there is no automatic Map-to-Read hidden in an adapter.
- No Crawl transport, page custody, candidate manufacture, evidence/citation/
  obligation authority, raw/private retention, or live call.
- Routing, acquisition control, topology artifact, exact-URL custody, and
  ordinary consumer tests pass offline.

## Stop And Split Conditions

Stop if topology selection requires a new model role, prompt redesign, ranking
system, or unresolved contract owner. Those are product decisions, not adapter
details. Do not absorb Crawl page custody: its per-page source identity,
multi-page packet, and EvidenceLedger consequences have a different owner and
rollback boundary.
