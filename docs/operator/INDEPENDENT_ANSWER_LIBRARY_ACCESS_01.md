## Implementation

`AnswerLibrary` adapts the existing `AcquisitionLibrary`, lexical SourceIndex,
immutable acquisitions, document extraction and exact views. It adds no semantic
owner, retrieval index, model ranker, summary store or persistent lifecycle.
Research instructions, provider selection, acquisition depth and understanding
remain unchanged. No localization, source-reading generation, finalization model
or forced browsing stage is restored.

An initial catalog and `library_browse` paginate 24 acquisition/document entries.
`library_find` and `library_read` return exact stored text through local-only
mechanics. Source IDs group versions; material IDs identify exact versions/views.
Navigation-only candidates, unread catalog entries, unacquired page portions and
other sessions cannot become support. The corpus is immutable; a returned view
may enter its existing in-memory material map. The local adapter refuses external
dispatch, even for a known navigation URL.

There are 12 local operations per Answer attempt, retained across correction;
the source-attention allowance is 128,000 characters including initial Evidence
and repeated local results. Normal results are bounded at 32,000 characters. An
already-acquired provider highlight up to its 65,536-character admission limit
can be returned whole, preserving its lack of page coordinates. Large full bodies
use exact bounded views. All continuations share existing Answer/run deadlines.

The API and official plan transport retain strict declared-tool allowlists and
argument/call-ID validation. Calculator calls coexist in the same continuation,
including multi-call responses and opaque encrypted reasoning replay. Diagnostic
receipts identify every exact exposed material, parent/version, range, SHA-256,
character count and UTF-8 byte count. Physical usage and request latency are
recorded separately from semantic attempts. No hidden reasoning is recorded.

Citation resolution receives the full set of text actually supplied to Answer.
Existing exact selected-material snapshots, SQLite sessions and the Reading Room
need no schema change. Catalog-only citations still fail. Bounded external-need
reentry compares selection against all prior Answer exposures and checks for new
acquisitions. A failed later attempt preserves an already-valid partial and its
original support; a hard bound retains the existing research-bound disclosure.
Pending new material is not represented as assessed or cited by that partial.
