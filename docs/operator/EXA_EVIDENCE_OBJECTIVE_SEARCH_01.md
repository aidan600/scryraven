## Basis and implementation

The completed Exa Query / Depth Calibration 01 supplied the bounded implication
to test natural-language queries next. Its objective formulations were promising,
especially with Deep; Auto results were comparable for BIPM and St. Dorothy's,
better for Passport, and mixed for MD-80. That calibration is consumed as given,
not reinterpreted or reopened. No Deep integration or routing experiment occurred.

The candidate replaces underspecified `query=the search` guidance in
`scryraven/research.py` with a concise natural-language objective describing what
source material should establish. It preserves consequential already-known entity,
relationship, source-class, time, scope, applicability and comparison constraints.
It discourages guessed keyword/Boolean/site syntax and unestablished answer facts,
while allowing useful proper nouns, exact terminology, quotations and source
constraints. Existing lexical Search remains the route for literal/site and
community/social/current navigation when that is the evidence need.

There is no string transformer, query-rewriter call, new semantic owner, schema,
provider/model router or product restriction. Non-prompt Research code, Request
and ResearchDecision schemas, Answer prompt, evidence selection, citation,
retention, failed-Read and novelty behavior are unchanged. Generic Search retains
Exa `type=auto`, six results, Dynamic/high Highlights and its beta header.
Serper, LinkUp static Fetch, Read and Find are unchanged. Research's
instruction-derived cache family changes automatically; Answer's does not.

## Query adjudication and interruption

All twenty generic queries are preserved verbatim in the ignored report and
`query-adjudication.json`, in case/request order. Classification:
18 `OBJECTIVE_ALIGNED`, one `ACCEPTABLE_NEUTRAL`, zero `KEYWORD_STYLE`, and one
`MISDIRECTED`. The neutral query is a simple official specification lookup for
the established Passport identity. The strict misdirection is the final
St. Dorothy's query: it requests confirmation of a candidate's appointment before
the appointment is established as Evidence. A prior lexical navigation result
named that candidate, and Research treated the lead as unverified; testing the
candidate was appropriate, but the confirming formulation biased the unresolved
relationship. No evidence demonstrates that this wording caused the failed Reads.
The three lexical queries are reported separately and are not graded by this rubric.
Objective-aligned queries can still be repetitive and unproductive.

The campaign wrapper reserved UTF-8 input byte count plus overhead and the full
12,000-token output allowance before each physical model request. Its deliberately
inflated Answer accounting rates were $10/$50 per million input/output tokens;
these were conservative accounting values, not verified billing tariffs. The
first Answer reservation remained outstanding until semantic completion. Reserving
a second full allowance for MD-80's calculator continuation projected beyond $3,
so the wrapper blocked that continuation. This was an overly conservative
campaign-plumbing error, not evidence that billed spend reached the hard cap.

The explicit preserved stop row is `campaign_ceiling`; the existing diagnostic
projection maps the wrapper's generic RuntimeError to `unexpected_failure`.
The run had already produced meaningful product observations, so the authorized
infrastructure replacement exception did not apply. No fifth run or reconstructed
Answer replay was attempted. No prompt-wording repair was made: the intended
query instruction was predominantly followed, and the incomplete Answer was not
a prompt-following failure.
