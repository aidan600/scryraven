## V2 candidate implementation

`scryraven.v2` implements exactly two semantic contracts, using GPT-5.6 Luna /
medium with Exa acquisition. Research interprets the immutable original question
and supplied actual Evidence, replaces a compact working understanding, chooses
independent Search/Read/Find requests, and proposes answering. The executor does
no semantic planning or truth judgment. The fresh Answer call receives exact
selected sources, conversation referents, operating date and mechanical limits.
It receives no Research findings, factual cautions, answer draft or verdict.

Within that same Answer call, transient literal `source_readings` precede prose.
Their membership in supplied material is mechanically checked, allowing only
whitespace variation and reconstructing the exact original substring. This does
not establish comprehension, faithful synthesis, or completeness: the campaign
demonstrated that true selected quotations can coexist with a materially incomplete
answer. A consequential missing need may return to the same Research loop and
remaining budget. There is no subsequent verifier or prose-polishing model.

Search mechanically admits actual extractive highlights, while navigation metadata
remains navigation. Read of an exact material ID is local by default; `full` obtains
or reuses a full parent, and `refresh` preserves a newly received version. Exact
view targets remain exact even with a focus; reading a parent can select new focused
views. Local Find and repeated reading reactivate retained material without refetch.
Overlapping Find hits from the same immutable parent can be consolidated without
losing selected text. Large exact ranges are delivered as bounded exact pieces.

Newly requested material receives attention first, and pending delivery prevents
another external route or answer proposal. Old material can be shelved without
deleting custody. Reference/exposure checks prevent catalog-only material from
silently becoming support. Same-URL acquisitions share canonical source identity;
exact versions and parent-relative views keep their own material IDs. Exposure
receipts demonstrate what was supplied, not what the model understood.

Default operating settings are 12 semantic attempts, 16 external acquisitions,
120 seconds, and 128,000 active Evidence characters. Invalid/corrected model calls
consume the same budget; local reading does not consume external allowance.
Transport timeouts use remaining time. One answer attempt is reserved where time
permits; an operational unable result is used if no source-grounded answer can be
completed. Bounds are not evidence of support or nonexistence.

The work item's separate ceiling is 50 submissions, with no run above
20 semantic attempts, 24 external attempts or 300 seconds. All 10 submissions used
the initial 12/16/120 settings. No model/provider replacement, router, premium
escalation, Scout, claim graph, confidence database or persistent hypothesis
lifecycle was introduced.

## Neutral results, sessions and citations

V2 returns `CompletedAnswer`, containing answer, posture, stop reason, immutable
acquisitions, exact selected material, citations, citation spans and safe trace.
It does not fabricate an Analysis object. `ResearchSession` uses its existing
engine injection boundary; V2 sees conversation referents and actual retained
Evidence, with fresh understanding and attention for each turn.

The existing SQLite SessionStore accepts neutral completed turns with
`analysis=None`, while decoding and preserving real legacy Analysis records.
Supported and partial neutral turns require exact citations at both the live
result and durable-store boundaries; unable turns may be citation-free.
Completed turns, acquired full parents, exact historical views and citation
material commit atomically with the existing revision check. Failed turns and
failed commits leave previous durable and in-memory state intact; stale writers
fail without semantic merging. Working notes, traces, observer records, provider
payloads and hidden reasoning are not durable session fields.

The V2 CLI supports isolated questions, `--session`, `--create-session`, `--resume`,
the shared database options, compact citations and standalone HTML. Supply `--v2`
for each candidate ask: engine choice is not persisted in a session. Reading Room
engine selection remains the baseline; V2 browser cognition is not demonstrated.
Shared rendering and historical inspection work with neutral saved turns in
deterministic tests. No full production migration or new browser engine selector
is claimed.

Citation resolution validates exact supplied material against immutable custody,
groups numeric citations by canonical source and preserves answer-local spans.
Actual selected versions/views remain inspectable after later acquisitions.
Mechanical identity validity is not semantic entailment or an exception-coverage
guarantee. Acquired source content remains untrusted display data and is escaped
by the shared presentation layer.

## Baseline production path retained

The default engine remains Research -> Analyst -> Author, both existing model
roles configured by default as GPT-5.6 Luna / medium. Exa Search supplies extractive
highlights; contextual needs can obtain fresh full text. The baseline retains its
32,000-character source packets, optional 48,000-character expansion, three
Analyst assessments and existing navigation/search accounting. V2 does not inherit
that one-expansion policy or Analyst semantics.

Earlier ordinary production observations demonstrated Bowling, IPCC Chapter 2,
NIST FIPS 197 and BIPM answers, with a partial Saturn snapshot outcome. The earlier
BIPM/BIPM/NASA session demonstrated retained-highlight reuse and durable reopening
across processes. Baseline live full-parent reuse and universal semantic fidelity
were not established. Relevant records remain in `docs/operator/`.

The local Reading Room uses Flask/Werkzeug on loopback at port 7331 by default,
with durable history, follow-ups, rename/delete, historical exact source inspection,
safe Markdown, working/failure states and responsive layouts. Its previous
real-browser acceptance used zero live provider calls. This work did not change
that UI or repeat its browser acceptance.

Stateless OpenAI Responses transport keeps `store=False` and explicit prompt
caching with a 30-minute TTL. The prior baseline three-turn cache observation
reported 23.62% fewer effective input units; that figure is not a V2 economy claim.
Safe usage observations exclude prompts, credentials, raw payloads and hidden
reasoning. The existing credential broker remains secret custody/process plumbing.
